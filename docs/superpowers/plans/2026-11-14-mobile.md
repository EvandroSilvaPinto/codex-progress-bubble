# Mobile sharing implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy an optional private session viewer with locally generated QR sharing on Cloudflare's free tier.

**Architecture:** One Worker serves static web assets and a capability-authenticated session API. D1 stores short-lived task metadata. A standard-library Python transport opts individual local/cloud tasks into sharing; existing desktop functionality stays local by default.

**Tech Stack:** Python 3.10+, JavaScript ESM/Node tests, Cloudflare Workers, D1 SQL, buildless HTML/CSS/JS, bundled QR encoder.

**Spec:** `docs/superpowers/specs/2026-11-14-mobile-design.md` (user approved).

## Global constraints

- Workers Free and D1 Free only; no paid upgrades or domains; no changes to unrelated Cloudflare resources.
- Separate 256-bit read/write capabilities, server-side authorization and expiry, 24-hour hard lifetime, one hour after first completion at most.
- No user accounts or global session listing. Upload only allowlisted task metadata after explicit opt-in.
- No QR service, analytics, third-party runtime resources, credential logging or committed secrets.
- Approximately 350 first-party implementation lines per new independently testable feature; Python desktop-only mode stays dependency-free.
- English README updated with every delivered change; pt/en viewer and sharing entry points.
- Work in existing checkout on `progress-bubble-mobile`; preserve main. User requested implementation and Cloudflare deployment, so continue through validated tasks without further routine approval.

## Review focus

- Parallel/out-of-order writes cannot resurrect an expired/completed task or overwrite newer state silently.
- Session A's reader/writer must never authorize session B or the other role.
- QR URL uses the reader capability only, decoded exactly; tokens never go to QR providers, logs or local writer-visible deliverables.
- Network failure leaves local status usable and does not silently duplicate remotely created sessions.
- Free-tier exhaustion fails closed and browser polling stops while hidden or after expiry/revocation.

## Tasks

### 1. Session model, storage and Worker API

**Files:** create `api/{worker,model,store,security}.js`, `api/migrations/0001.sql`, `api/tests/*.test.js`, `package.json`, `wrangler.jsonc`; modify ignores and README.

**Interfaces:** POST /api/sessions accepts allowlisted snapshot plus a client-generated creation ID for idempotency. GET/PATCH/DELETE /api/sessions/:id use role-specific bearer capabilities. Public snapshot includes version, expires_at and allowlisted progress fields only. Storage is private D1; parameterized SQL uses id and capability hash. Reject invalid status/percent, oversized metadata and stale versions.

- [ ] Implement same-origin static fallback, no-store/no-referrer/CSP headers, bounded request bodies and creation limits.
